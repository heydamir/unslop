# Travel Unslop

이 스킬은 Damir Sokolovsky([@heydamir](https://x.com/heydamir))가 만든 unslop을 여행사 홈페이지용으로 변형한 것입니다. 원본은 CC BY 4.0 라이선스이므로, 복사본이나 변형본에도 이 출처 표기를 유지하세요.

여행사 홈페이지는 늘 같은 방식으로 실패합니다. 검색은 배너 캐러셀 아래에 묻히고, 모든 카드에 `특가` 배지가 붙고, 어느 바다인지 모를 스톡 사진 위에서 카피가 소리를 지르고, 진짜 가격은 결제 직전에야 나타납니다. 이 스킬은 만듦새를 고치고 여행사와 상품은 그대로 둡니다. 바뀌는 것은 모든 크기, 색, 단어, 사진, 숫자가 의도를 갖게 된다는 점입니다.

깔끔해지는 것은 일의 절반입니다. 깔끔하지만 어느 여행사에나 어울리는 화면은 다음 템플릿일 뿐입니다. 모든 작업은 이 여행사만이 가질 수 있는 화면으로 끝나야 합니다.

## 세 개의 축

여행사 홈페이지는 세 가지를 동시에 해내야 합니다.

- **검색.** 방문자는 "어디로, 언제, 누구와"를 갖고 들어옵니다. 화면은 그것을 가장 적은 동작으로 받습니다.
- **감성.** 방문자가 그곳에 있는 자신을 상상하게 만듭니다. 그 일은 목적지 사진이 합니다.
- **신뢰.** 결국 얼마인지, 무엇이 들어 있는지, 못 가면 어떻게 되는지를 묻기 전에 답합니다.

셋이 부딪칠 때의 규칙입니다.

- 사진은 검색을 가리지 않습니다. 검색 위젯과 헤드라인이 읽히지 않는 사진은 다른 사진으로 바꿉니다.
- 감성은 사실을 넘지 않습니다. 사진은 실제로 가는 곳이고, 카피는 실제 조건입니다.
- 신뢰는 전환보다 먼저입니다. 가짜 긴급성, 숨은 요금, 미리 체크된 옵션은 예약을 늘려 보여도 쓰지 않습니다.
- 감성의 크기는 흐름을 따라 줄어듭니다. 메인에서 가장 크고, 결제 화면에서는 거의 없습니다. 화면은 뒤로 갈수록 조용하고 정확해집니다.

슬롭과 만듦새의 차이는 풍부함이 어디로 가느냐입니다. 슬롭은 색과 효과를 배경, 버튼, 테두리, 배지에 흩뿌립니다. 만듦새는 크롬을 조용하게 두고, 풍부함을 목적지 사진 한 장에 쏟습니다.

## 좋은 결과의 모습

- **주인공 사진 한 장.** 각 화면에는 색과 감정을 담당하는 사진이 하나 있고, 어디인지 알 수 있는 장소입니다. 그 주변은 조용해서 사진이 즉시 읽힙니다.
- **첫 화면 안의 검색.** 스크롤 없이 목적지, 날짜, 인원을 고를 수 있고, 검색 버튼이 첫 화면의 유일한 액센트입니다.
- **조용한 크롬.** 내비게이션, 카드, 텍스트는 틴트된 뉴트럴과 액센트 하나를 씁니다. 아무것도 빛나거나 깜빡이지 않습니다.
- **정직한 숫자.** 처음 본 가격이 결제 금액이고, 가격 옆에 기준과 포함 여부가 있습니다.
- **보이는 절차.** 예약이 몇 단계인지, 지금 어디인지, 합계가 얼마인지 항상 보입니다.
- **고요한 공간 위의 텍스트.** 헤드라인은 사진에서 비어 있는 영역에 놓이고, 짧고, 이 여행사만의 말입니다.

## 실행하기

먼저 어느 모드인지 정합니다. 고칠 화면이 있으면 개선 모드, 없으면 신규 모드입니다.

### 개선 모드

1. **화면을 봅니다.** 화면을 렌더링하는 파일을 찾습니다. 앱을 실행하거나 브라우저에서 열어 스크린샷을 찍을 수 있다면 그렇게 해서, 코드만이 아니라 방문자가 실제로 보는 것을 판단합니다. 모바일 너비도 함께 봅니다.
   - 코드 없이 라이브 사이트 링크만 있다면 `node <skill folder>/scripts/snapshot.mjs <url> unslop/original.html`로 페이지를 저장하고 그 파일의 복사본에서 작업합니다. URL 대신 로컬 HTML 파일도 됩니다. `--dark`나 `--light`로 테마를 맞출 수 있습니다. 라이브 페이지의 스크린샷 `original.live.png`도 함께 저장되므로, 저장된 복사본을 렌더링해 둘을 비교한 뒤 시작합니다. Playwright가 필요하므로 없으면 설치 명령 하나를 사용자에게 알려줍니다.
   - 스크린샷만 있다면 먼저 화면을 정적 HTML 파일 하나로 가깝게 재구성하고 그것을 원본으로 삼습니다.
   - 두 경우 모두 결과물은 코드로 된 리디자인 페이지이고, 사용자가 실제 사이트 담당자에게 넘길 수 있습니다. 보고서에 그렇게 씁니다.
2. **감사합니다.** [references/signs.md](references/signs.md)를 훑으며 발견한 징후를 위치와 함께 한 줄씩 적습니다. 검색, 가격과 예약, 여행 비주얼과 카피 그룹을 먼저 봅니다.
3. **얼마나 바꿀지 정합니다.**
   - **심한 슬롭.** 여러 그룹에 걸쳐 징후가 많습니다. 아래 전체 과정을 실행합니다.
   - **가벼운 슬롭.** 대체로 설계되어 있고 몇 가지만 남았습니다. 감사에서 찾은 것만 고치고, 방향은 기존 브랜드에서 가져오며, 팔레트, 서체, 레이아웃, 사진은 유지합니다. 더 큰 아이디어는 보고서에 제안으로 씁니다.
   - **슬롭 없음.** 그렇다고 분명히 말하고, 정확한 값과 함께 두세 가지 작은 개선만 제안합니다. 사용자가 동의할 때만 적용합니다. 좋은 화면을 다르게 만들려고 바꾸지 않습니다.
   - 가격과 예약 그룹의 징후는 슬롭의 정도와 상관없이 항상 보고합니다. 방문자가 돈을 잃을 수 있는 문제이기 때문입니다.
4. **방향을 정하고 멈춥니다.** 아래의 여섯 줄을 씁니다. 감사 결과, 방향, 그리고 확인이 필요한 사실의 목록을 사용자에게 보여주고 답을 기다립니다. 질문 도구가 있으면 그것으로 묻고, 없으면 글로 묻고 멈춥니다. 사용자가 이미 그냥 진행하라고 했을 때만 건너뜁니다.
5. **아홉 패스로 순서대로 고칩니다.** 한 패스를 화면 전체에 끝낸 뒤 다음으로 갑니다. 거의 모든 줄이 바뀐다면 패스를 순서대로 계획한 뒤 새 화면을 한 번에 써도 되지만, 모든 패스가 적용되어야 합니다.
6. **점검합니다.** 이 파일 끝의 체크리스트를 돌리고, 데스크톱과 모바일 너비로 다시 렌더링해 감사 목록과 비교합니다. 남은 것은 고칩니다.
7. **보고합니다.** 아래 [보고서](#보고서)의 형식으로 씁니다.

### 신규 모드

1. **재료를 확인합니다.** 여행사 이름과 브랜드 자산, 주력 상품과 주 고객, 대표 목적지, 만들 화면, 프로젝트의 스택과 기존 컴포넌트, 쓸 수 있는 사진, 실제 상품 데이터가 있는지. 대화와 프로젝트에서 찾을 수 있는 것은 찾고, 없는 것만 묻습니다.
2. **방향을 정하고 멈춥니다.** 개선 모드와 같습니다.
3. **구조를 잡습니다.** [references/pages.md](references/pages.md)에서 만들 화면의 구성을 가져와 이 여행사에 맞게 줄이고 순서를 정합니다. 섹션 목록을 방향과 함께 사용자에게 보여줍니다.
4. **아홉 패스의 규칙으로 만듭니다.** 패스의 순서대로 결정하고, 화면은 한 번에 써도 됩니다.
5. **점검하고 보고합니다.** 개선 모드와 같습니다.

작업은 빠르게 합니다. 확인을 위한 렌더링은 데스크톱과 모바일을 한 쌍으로 쳐서 최대 세 번입니다.

각 패스의 정확한 값은 [references/tokens.md](references/tokens.md)에 있습니다.

## 방향

무엇이든 건드리기 전에 짧은 여섯 줄을 씁니다. 화면이 말하는 이 여행사의 상품과 고객에서 도출합니다. 유행이나 대형 OTA의 모습에서 가져오지 않습니다.

- **여행사.** 무엇을 누구에게 파는지 평이한 한 문장으로. 예: `부모님을 모시고 가는 일본 온천 패키지를 파는 여행사`.
- **캐릭터.** 구체적인 두세 단어. `느긋하고, 따뜻하고, 꼼꼼한` 또는 `빠르고, 가볍고, 솔직한`. 깔끔한, 모던한, 세련된, 감성적인, 프리미엄 같은 단어는 모든 템플릿을 설명하므로 쓰지 않습니다.
- **세계.** 이 여행사의 여행이 자연스럽게 속하는 장소와 재질. 온천 여행은 김이 오르는 물과 나무와 유카타 가까이에, 동남아 휴양은 이른 아침의 바다와 리넨 가까이에, 유럽 일주는 돌바닥과 기차역과 종이 지도 가까이에 있습니다. 이 세계가 뉴트럴의 틴트, 액센트, 사진의 분위기를 정합니다.
- **주인공.** 화면에서 색과 감정을 담당할 한두 곳. 어느 목적지의, 어떤 빛의, 어떤 구도의 사진인지 한 문장으로 씁니다.
- **약속.** 이 여행사가 가격과 예약에 대해 지킬 수 있는 사실 한두 가지. 화면이나 사용자가 확인해 준 것만 씁니다. `모든 가격은 유류할증료 포함 총액`, `출발 30일 전까지 무료 취소`. 확인된 것이 없으면 비워 두고 사용자에게 묻습니다.
- **시그니처.** 이 여행사만 가질 작은 디테일 하나를 일관되게 씁니다. 사진마다 붙는 장소 캡션, 일정을 잇는 경로선, 탑승권 모양의 예약 요약, 날짜 옆의 현지 날씨. 다섯 개가 아니라 하나입니다.

여기의 예시는 답의 형태만 보여줍니다. 예시가 맞아 보여도 눈앞의 여행사에서 직접 도출합니다.

여행사에 이미 진짜 브랜드가 있다면, 즉 슬롭이 아닌 로고, 색, 서체가 있다면 유지하고 그 주위로 방향을 세웁니다. 보라-파랑 그라디언트, 반짝이, 글로우는 로고에 있어도 슬롭이며, 사용자가 브랜드라고 말하지 않는 한 브랜드로 치지 않습니다.

## 1. 간격

- 모든 것은 4px 그리드 위에 놓입니다. 마진, 패딩, 갭, 고정 높이는 4의 배수입니다. 작은 컨트롤 안의 미세 조정에는 2px도 괜찮습니다.
- 같은 것은 같은 크기입니다. 한 그리드의 카드는 같은 패딩과 같은 사진 비율을, 한 목록의 행은 같은 높이 규칙을 갖습니다.
- 간격이 그룹을 보여줍니다. 그룹 안의 간격이 그룹 사이의 간격보다 작습니다. 카드 안에서 상품명과 일정 요약은 가깝고, 가격은 떨어져 있습니다.
- 정렬합니다. 아이콘은 한 열에, 라벨은 한 선에서 시작하고, 가격은 오른쪽 정렬된 한 열에 놓입니다.
- 검색 위젯의 필드는 같은 높이, 같은 안쪽 패딩, 같은 라벨 위치를 갖습니다.
- 손가락이 닿는 영역은 44×44 이상입니다.
- `mt-[13px]` 같은 일회성 값은 스케일의 단계로 바꿉니다.

## 2. 색

- 하나의 뉴트럴 램프에서 만들고, 방향의 세계 쪽으로 틴트합니다. 배경, 카드, 테두리, 텍스트가 모두 그 램프에서 나옵니다.
- 라이트 테마가 기본입니다. 표면은 사진을 방해하지 않는 뉴트럴이고, 색은 사진이 담당합니다.
- 텍스트 역할은 주, 보조, 흐림 세 가지입니다. 가격, 날짜, 취소 규정 같은 예약 판단 정보는 흐린 텍스트로 쓰지 않습니다.
- 크롬의 액센트는 하나이고 드물게 씁니다. 검색 버튼, 예약 버튼, 선택된 날짜, 현재 예약 단계.
- 가격은 주 텍스트 색입니다. 빨간 가격, 액센트 색 가격으로 소리 지르지 않습니다.
- 브랜드에 진짜 색이 있으면 그것이 액센트가 되고 표면에서는 떠납니다. 없으면 세계에서 가져옵니다.
- 액센트 위의 텍스트, 사진 위의 텍스트는 4.5:1 대비에 도달합니다.
- 상태 색은 의미만 담고 톤을 낮춥니다. 색만으로 알리지 않고 항상 글자를 함께 씁니다.
- 표면의 색조 그라디언트, 그라디언트 텍스트, 컬러 글로우와 컬러 그림자, 블롭, 네온 테두리는 제거합니다. 사진 위의 검정-투명 스크림은 색조 그라디언트가 아니므로 허용됩니다.
- 테두리는 램프의 텍스트 색을 6~10% 불투명도로 쓴 헤어라인이고, 그림자는 뉴트럴하고 부드럽고 작습니다.

## 3. 아이콘

- 아이콘이나 장식으로 쓰인 모든 이모지는 하나의 세트에서 가져온 라인 아이콘이 됩니다. 프로젝트에 이미 있는 세트를 쓰고, 없으면 lucide를 씁니다.
- 하나의 크기와 스트로크, 18 또는 20px에 1.5 스트로크입니다.
- 아이콘은 자기 텍스트 역할의 색을 따릅니다.
- 검색 필드 앞, 포함 사항 목록, 일정의 이동 수단처럼 훑어보기를 돕는 곳에만 씁니다. 모든 카드 제목과 섹션 제목 앞의 아이콘은 뺍니다.
- 포함과 불포함의 체크와 엑스는 같은 세트, 같은 크기입니다.

## 4. 카피

- 헤드라인은 이 여행사가 누구에게 무엇을 파는지 평이한 말로 하며, 이름만 바꿔서는 다른 여행사에 맞지 않아야 합니다. 화면에 이미 있는 사실을 쓰고 새로 지어내지 않습니다.
- 느낌표, 물결, 말머리, 특수문자를 쓰지 않습니다. `초특가!!!`, `떠나요~`, `[마감임박]`, `★`.
- 과장 단어를 쓰지 않습니다. 역대급, 초특가, 파격, 인생 여행, 꿈의, 환상적인. 대신 실제 조건과 숫자를 씁니다.
- 상품명은 목적지, 기간, 핵심 특징입니다. `다낭·호이안 3박 5일 · 5성급 리조트 · 노쇼핑`.
- 라벨은 짧게 씁니다. `어디로 떠나시나요?`가 아니라 `목적지`.
- 버튼은 누르면 일어나는 일을 말합니다. `3,770,000원 결제하기`, `예약 상담 신청`, `출발일 선택`.
- 가격에는 기준과 포함 여부가 붙습니다. `성인 1인 · 유류할증료·제세공과금 포함`.
- 헤드라인, 라벨, 버튼, 캡션은 마침표 없이 끝납니다. 여러 문장으로 된 문단만 마침표를 씁니다.
- 말투는 하나로 통일합니다. 안내와 설명은 `합니다`체가 기본이고, 버튼과 라벨은 명사형이나 `하기`형입니다.
- 확인할 수 없는 주장, 즉 잔여석, 마감일, 할인율, 후기 수, 누적 고객 수, 수상 내역은 사용자가 사실이라고 확인하면 조용하고 구체적으로 바꾸고, 아니면 제거합니다. 묻고, 보고서에 나열합니다.
- 목업 데이터는 진짜처럼 보여야 합니다. 실제 공항 코드, 그럴듯한 가격과 항공편 시각, 실제로 존재하는 요일과 날짜.
- 가격, 포함과 불포함, 취소 규정, 예약 종류의 문구는 [references/booking.md](references/booking.md)를 따릅니다.

## 5. 타입

- 방향의 캐릭터에 맞는 서체를 토큰에서 고릅니다. 프로젝트의 서체가 진짜 브랜드의 일부라면 유지합니다. 한글, 영문, 숫자가 한 서체로 해결되는 것을 고르고, 큰 헤드라인에만 파트너 하나를 더할 수 있습니다.
- 굵기는 400, 500, 600입니다. 위계는 굵기가 아니라 크기와 색에서 나옵니다.
- 한글은 줄 높이를 넉넉하게, 본문 1.6 근처로 잡고, `word-break: keep-all`로 단어 단위로 끊습니다.
- 숫자는 `tabular-nums`와 화면 전체에서 하나의 형식을 씁니다. `1,290,000원`. 날짜도 하나의 형식입니다. `5월 12일 (월)`.
- 가격의 `원`은 숫자보다 작게, 같은 기준선에 둡니다.
- 영문 대문자에 넓은 자간을 준 라벨은 한글 라벨로 바꿉니다. `POPULAR DESTINATIONS`는 `인기 여행지`입니다.
- 손글씨 서체, 장식 서체, 그라디언트 텍스트, 텍스트 외곽선을 쓰지 않습니다.
- 본문 한 줄은 한글 35~45자를 넘기지 않습니다.

## 6. 레이아웃

- 개선 모드에서는 섹션과 그 순서를 유지합니다. 섹션 안의 정렬과 비율은 화면이 명확해질 때 바꿀 수 있습니다. 한 가지 예외는 검색 위젯입니다. 첫 화면 밖에 있다면 첫 화면 안으로 올리고, 보고서에 씁니다.
- 메인의 첫 화면은 사진, 헤드라인, 검색이 하나의 구성입니다. 사진이 폭을 채우고, 헤드라인은 사진의 고요한 영역에, 검색 위젯은 사진의 아래쪽에 걸쳐 놓입니다.
- 검색 위젯은 불투명한 표면 하나에 필드가 한 줄로 놓이고, 끝에 액센트 버튼이 있습니다. 상세는 [references/search.md](references/search.md)에 있습니다.
- 헤더는 조용합니다. 로고, 상품 분류, 예약 조회, 로그인. 버튼은 최대 하나입니다.
- 상품 그리드는 크기에 리듬을 줍니다. 같은 너비의 카드가 끝없이 반복되면 템플릿으로 읽힙니다. 목적지 탐색은 큰 카드 하나와 작은 카드 여러 개처럼 구성합니다.
- 검색 결과는 왼쪽 필터와 오른쪽 목록, 상품 상세와 예약은 왼쪽 본문과 오른쪽에 고정된 요금 패널입니다.
- 상품 상세는 결정에 필요한 순서로 놓습니다. 사진, 요금과 출발일, 포함과 불포함, 일정, 취소 규정. 긴 화면에는 고정된 앵커 탭을 둡니다.
- 예약 화면은 헤더를 줄이고, 프로모션과 추천 상품을 넣지 않습니다.
- 팝업, 전면 배너, 여러 개의 플로팅 버튼은 없앱니다.
- 작은 화면에서는 읽는 순서대로 쌓이고, 검색은 전체 화면 시트로, 요금 패널은 하단 고정 바로 바뀝니다. 표는 가로 스크롤 대신 카드로 바꿉니다. 텍스트는 12px 아래로 내려가지 않습니다.
- 화면별 구성은 [references/pages.md](references/pages.md)에 있습니다.

## 7. 디테일

- 중첩 라디우스. 안쪽 라디우스는 바깥 라디우스에서 패딩을 뺀 값이고, 4보다 작아지지 않습니다. 모든 것이 필은 아닙니다.
- 배지는 조용한 텍스트입니다. `BEST`, `HOT`, `특가`는 없애고, `출발 확정`, `잔여 3석`처럼 실제 상태만 상태 색의 작은 텍스트로 남깁니다. 카드 하나에 최대 하나입니다.
- 달력의 날짜 칸은 날짜와 가격 두 줄이고, 선택된 날은 액센트 채움, 범위는 옅은 틴트, 불가능한 날은 흐립니다.
- 스테퍼는 `−` 숫자 `+`이고, 한계에서 버튼이 비활성화되며 이유가 한 줄로 보입니다.
- 요금 요약은 줄 단위로 쌓이고, 금액은 오른쪽 정렬된 `tabular-nums`, 합계 위에 헤어라인, 합계가 가장 큰 숫자입니다.
- 진행 표시는 숫자와 이름이 있는 단계이고, 현재 단계만 액센트입니다.
- 출발일별 요금표와 취소 수수료 표는 헤어라인으로 나눈 조용한 표입니다. 줄무늬 배경과 색이 든 헤더를 쓰지 않습니다.
- 일정표는 일차별 타임라인이고, 날짜마다 도시, 방문지, 식사, 숙소가 같은 구조로 놓입니다.
- 포함과 불포함은 같은 크기, 같은 색, 같은 무게의 두 열입니다.
- 모든 컨트롤에 호버, 포커스, 비활성, 오류 상태가 있고 팔레트 안에 머뭅니다. 키보드 사용자를 위한 포커스 링이 보입니다.
- 로딩은 카드 모양의 스켈레톤, 결과 없음은 대안 제안, 오류는 다시 시도 버튼입니다.
- 푸터의 사업자 정보는 읽을 수 있는 크기와 대비입니다.
- 방향의 시그니처 디테일은 속한 곳에 나타나고 다른 곳에는 나타나지 않습니다.

## 8. 비주얼

- 장식용 채움재는 없앱니다. 그라디언트 위의 비행기와 지구본, 블롭, 구름 모양, 색종이, 스톡 일러스트.
- 히어로는 어디인지 알 수 있는 목적지 사진 한 장입니다. 자동 캐러셀은 쓰지 않습니다.
- 사진은 여행사가 가진 것, 권한이 확인된 것의 순서로 구하고, 없으면 정확한 크기의 빈 슬롯을 두고 어떤 사진이 필요한지 보고서에 씁니다.
- 생성 이미지를 실제 목적지, 호텔, 객실, 음식 사진 자리에 쓰지 않습니다. 특정 장소를 가리키지 않는 분위기 이미지나 구도 확인용 임시 이미지에만 쓰고, 보고서에 표시합니다.
- 장소를 알 수 없는 스톡, 채도를 끝까지 올린 사진, 카메라를 보는 모델, 여권과 모형 비행기 사진은 바꿉니다.
- 한 그리드의 사진은 같은 비율이고, 한 화면의 사진은 한 사람이 찍은 것처럼 색온도와 거리가 비슷합니다.
- 사진 위에는 최대 두 가지만 올립니다. 텍스트 대비는 사진 선택으로 먼저 해결하고, 부족하면 텍스트 쪽에만 뉴트럴 스크림을 깝니다.
- 글자가 구워진 통이미지로 일정, 가격, 규정을 전달하지 않습니다. 실제 텍스트로 옮깁니다.
- 모든 사진에 고정 비율과 `alt`가 있고, 히어로는 먼저, 나머지는 지연 로드합니다.
- 사진 고르는 법과 히어로 구성은 [references/visuals.md](references/visuals.md)에 있습니다. 이 패스 전에 읽습니다.

## 9. 모션

- 이유 없이 반복되는 모션을 없앱니다. 깜빡이는 `마감 임박`, `animate-pulse`, 숨쉬는 글로우, 떠다니는 요소, 패럴랙스, 자동으로 넘어가는 배너.
- `transition-all`, 튀는 스프링, 카드의 `hover:scale`, 크게 확대되는 사진을 없앱니다.
- 무언가를 설명하는 모션은 남깁니다. 호버는 빠른 색이나 표면 변화, 프레스는 아주 작은 스케일 다운, 달력과 자동완성은 열리는 곳에서 몇 픽셀 페이드하며 올라오고, 바뀐 합계는 숫자가 트윈됩니다.
- color, background, border, opacity, transform만 전환하고 이름을 명시합니다. width, height, top, left, 마진, 큰 블러는 애니메이션하지 않습니다.
- 화면 전체에 이징 곡선 하나와 몇 가지 지속 시간을 씁니다.
- 로드 시 등장은 최대 한 번, 작은 스태거의 짧은 페이드와 라이즈입니다.
- 영상은 무음의 짧은 루프이고 정지할 수 있습니다. `prefers-reduced-motion: reduce`에서는 등장과 자동 재생을 끕니다.

## 보고서

- **방향.** 여섯 줄.
- **패스별 변경.** 패스마다 무엇이 바뀌었는지 몇 줄.
- **확인 필요.** 사용자가 사실 여부를 확인해야 하는 것. 가격 구성과 포함 여부, 취소 수수료 기준, 잔여석과 마감 표시, 할인 정가, 후기와 수치, 사업자와 등록 정보, 관련 법령과 약관에 따른 표기. 화면에서 제거했거나 자리만 남긴 것도 여기에 씁니다.
- **필요한 사진.** 빈 슬롯마다 파일명, 크기, 어떤 사진인지 한 문장. 임시로 넣은 생성 이미지가 있으면 맨 위에 씁니다.
- **제안.** 범위 밖이어서 바꾸지 않은 것. 빠진 섹션, 더 나은 예약 흐름.

## 하지 말 것

- 여행사 이름을 바꾸지 않고, 진짜 로고는 그대로 둡니다. 로고 자체가 슬롭이면 평평하게 다시 그립니다. 새 서체의 워드마크만 쓰거나, 단색의 단순한 글리프를 씁니다.
- 상품을 바꾸지 않습니다. 일정, 가격, 포함 사항, 섹션 순서는 사용자가 요청하지 않는 한 유지합니다. 의미 없는 플레이스홀더는 의미 있는 내용으로 바꿔도 됩니다.
- 사실을 지어내지 않습니다. 가격, 잔여석, 할인, 후기, 수상, 취소 수수료율, 등록번호, 보험 가입 내용. 화면에 없으면 자리만 두고 묻습니다.
- 법률 판단을 하지 않습니다. 표기 의무와 수수료 기준은 확인 필요 항목으로 넘깁니다.
- 방문자를 속이는 설계를 넣지 않습니다. 가짜 타이머, 꾸며낸 예약 알림, 미리 체크된 옵션, 거절을 부끄럽게 만드는 문구, 숨긴 추가 요금. 사용자가 요청해도 넣지 않고 이유를 설명합니다.
- 제거한 장식을 새 장식으로 바꾸지 않고, 하나의 유행을 다른 유행으로 바꾸지 않습니다. 글래스, 그레인, 네온, 벤토 그리드.
- 대형 OTA의 화면을 그대로 옮기지 않습니다. 팔레트, 서체, 사진, 검색 탭의 순서는 습관이 아니라 방향이 정합니다.

- [ ] 모든 간격 값이 4px 스케일 위에 있고 같은 것은 같은 크기다
- [ ] 틴트된 뉴트럴 램프 하나, 텍스트 역할 셋, 대비가 충분한 액센트 하나
- [ ] 색조 그라디언트, 그라디언트 텍스트, 글로우, 컬러 그림자, 블롭이 없다
- [ ] 인터페이스에 이모지가 없고, 하나의 크기와 스트로크를 가진 아이콘 세트 하나다
- [ ] 굵기 400~600, 한글 줄 높이와 `keep-all`, 손글씨와 장식 서체 없음
- [ ] 느낌표, 물결, 말머리, 과장 단어, 검증되지 않은 주장이 없다
- [ ] 중첩 라디우스가 맞아떨어지고 모든 컨트롤에 포커스 상태가 있다
- [ ] 반복되거나 튀는 모션이 없고, 이징 곡선은 하나다

검색

- [ ] 검색 위젯이 데스크톱과 모바일의 첫 화면 안에 있다
- [ ] 필드마다 보이는 라벨이 있고, 출발지와 인원에 기본값이 있다
- [ ] 검색 버튼이 첫 화면의 유일한 액센트 채움 버튼이다
- [ ] 목적지는 자동완성과 인기 지역, 날짜는 범위 달력, 인원은 나이 기준이 있는 스테퍼다
- [ ] 결과 목록에 조건 요약, 결과 수, 정렬, 지울 수 있는 필터 칩이 있다
- [ ] 로딩, 결과 없음, 오류 상태가 설계되어 있고 결과 없음은 대안을 준다
- [ ] 모바일의 터치 영역이 44 이상이고 입력 글자가 16px 이상이다

감성

- [ ] 화면의 주인공이 어디인지 알 수 있는 목적지 사진 한 장이다
- [ ] 헤드라인과 검색이 사진의 고요한 영역에 놓이고 대비가 4.5:1 이상이다
- [ ] 자동 캐러셀, 장식 일러스트, 여행 소품 스톡이 없다
- [ ] 한 그리드의 사진이 같은 비율이고 한 화면의 사진이 한 세트처럼 보인다
- [ ] 생성 이미지가 실제 장소나 숙소 사진 자리에 없다
- [ ] 글자가 구워진 이미지로 전달되는 정보가 없다

신뢰

- [ ] 모든 가격에 기준과 포함 여부가 붙어 있고 한 가지 형식이다
- [ ] 카드, 상세, 요금 요약, 결제 버튼의 금액이 같은 기준이고 서로 맞는다
- [ ] 추가 요금과 현지 지불 금액이 상품 상세에서 공개된다
- [ ] 포함과 불포함이 같은 무게로 나란히 있다
- [ ] 예약 단계와 현재 위치가 보이고 요금 요약이 모든 단계에 고정되어 있다
- [ ] 취소 수수료가 결제 전 화면에 표로 있다
- [ ] 주 버튼의 라벨이 결제인지 신청인지 말한다
- [ ] 가짜 긴급성, 미리 체크된 옵션, 근거 없는 줄 그은 정가가 없다
- [ ] 사업자 정보와 고객센터 운영 시간이 읽을 수 있는 크기로 있다
- [ ] 지어낸 사실이 없고, 확인이 필요한 것은 보고서에 나열되어 있다

마지막

- [ ] 템플릿 점검. 여행사 이름과 로고를 다른 여행사의 것으로 바꿔도 화면이 여전히 들어맞는가? 그렇다면 헤드라인, 사진, 검색 탭의 순서, 시그니처 디테일에서 방향을 더 밀어붙인다
